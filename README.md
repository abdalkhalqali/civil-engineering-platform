# civil-engineering-platform

Civil Engineering Design & BIM Platform — Engineering Model First architecture. Cross-platform Flutter + Rust core.

## Repository layout

```
core/geometry_kernel_rs/     Rust geometry kernel (cdylib + staticlib + rlib)
  src/api.rs                 Public Rust API exposed to Flutter
  src/model/                 EngineeringModel — the single source of truth
  src/elements/              Column, Beam, Slab, Wall, Foundation
  src/math/                  Point3D, Vector3D, Transform3D
  src/units/                 internal SI quantities
  src/commands/              model mutations (extension point)
  tests/                     engineering model test suite
  src/frb_generated.rs       Generated by flutter_rust_bridge (do not edit)
apps/client_flutter/         Flutter application
  lib/ffi_bridge/generated/  Generated Dart bindings (do not edit)
  rust_builder/              cargokit glue that builds and bundles the kernel
  flutter_rust_bridge.yaml   Configuration for the code generator
docs/                        ENGINEERING_MODEL.md, ARCHITECTURE.md
```

## Engineering Model Core

The engineering model is the single source of truth: levels, grids, materials, cross
sections and elements, in internal SI units, related by stable ids.

```text
EngineeringModel
├── levels          Level 1, Level 2
├── grids           A, B, 1, 2
├── materials       Concrete C30
├── cross_sections  400x400
└── elements        Column C001, Beam B001
```

Rules the model enforces: SI units only (400 mm is stored as `0.4 m`), relationships by
id (never embedded copies), derived values computed rather than stored (area, inertia,
lengths), and validation that reports — without silently repairing — duplicate ids,
dangling references, inconsistent categories, non-positive dimensions and unusable
extents. Schema version `1` is stored with the data.

## Rust ↔ Flutter bridge

Pinned toolchain: Rust 1.98.1, Flutter 3.47.4 (Dart 3.13.3), flutter_rust_bridge 2.13.0
for both the Dart package and the Rust crate.

Exposed today: `get_kernel_status()` (connectivity proof of concept) and
`create_empty_model()` (a flat summary of a Rust-side model). The model itself never
crosses the boundary.

### Generate the bindings

```bash
cargo install flutter_rust_bridge_codegen --version 2.13.0   # or use the prebuilt release binary
cd apps/client_flutter
flutter_rust_bridge_codegen generate
```

Everything under `lib/ffi_bridge/generated/` and `core/geometry_kernel_rs/src/frb_generated.rs`
is produced by the generator and must never be edited by hand.

### Verify

```bash
cd core/geometry_kernel_rs && cargo check && cargo test
cd ../../apps/client_flutter && flutter pub get && flutter analyze && flutter test
```

Host-side bridge check against a locally built library:

```bash
cd core/geometry_kernel_rs && cargo build
cd ../../apps/client_flutter
FRB_DART_LOAD_EXTERNAL_LIBRARY_NATIVE_LIB_DIR=../../core/geometry_kernel_rs/target/debug flutter test
```
