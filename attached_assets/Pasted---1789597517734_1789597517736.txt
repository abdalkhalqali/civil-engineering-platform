ARCHITECTURAL APPROVAL + REQUIRED ADJUSTMENTS

نعتمد المشروع كمنصة Civil Engineering / BIM احترافية طويلة الأجل، وليس كتطبيق 3D Viewer.

========================================

1. FOUNDATION HARDENING
   ========================================

ابدأ أولًا بإغلاق فجوة Project Persistence:

ProjectFormatV1::deserialize()
يجب أن يتحقق تلقائيًا من:

Header
Format Version
Model Schema Version
Project ID
Model Validation

ويجب أن يؤدي فشل:

model.validate()

إلى:

ProjectError::ModelValidationFailed

مع عدم وجود أي silent repair.

أضف فقط اختبارات regression الضرورية.

يجب أن تستمر جميع الاختبارات السابقة.

========================================
2. RUST TOOLCHAIN

الإصدار المرجعي للمشروع:

Rust 1.98.1

لكن:

لا تفرض Rust 1.98.1 بطريقة قد تجعل Replit غير قابل للبناء.

تحقق أولًا من توفر الإصدار.

إذا كان متاحًا وآمنًا من ناحية البيئة والمساحة:

يمكن إضافة rust-toolchain.toml.

إذا لم يكن متاحًا:

سجل ذلك كـ environment limitation.

لا تغيّر source architecture بسبب اختلاف نسخة Rust في Replit.

========================================
3. FLUTTER / DART

الإصدارات المرجعية:

Flutter 3.47.4
Dart 3.13.3
flutter_rust_bridge 2.13.0

لكن لا تقم بتنزيل Flutter SDK ضخم أو أي dependencies كبيرة لمجرد اجتياز الاختبار إذا كانت مساحة Replit محدودة.

إذا كان Flutter/Dart غير متوفر:

سجل:

NOT TESTED — ENVIRONMENT LIMITATION

ولا تعتبر ذلك فشلًا في Rust Core.

4. ARABIC FOUNDATION

نريد الآن فقط تأسيس البنية العربية، وليس بناء تطبيق إدارة مشاريع كامل.

أنشئ:

Arabic localization foundation
RTL support
ARB structure
supportedLocales
localizationsDelegates
Arabic-first theme/text direction
English fallback architecture

يجب أن تكون الواجهة الحالية عربية ومنظمة.

لكن:

لا تنفذ الآن نظام إدارة مشاريع كامل.

لا تنفذ صفحات كثيرة.

لا تنفذ UI logic يحتوي على Engineering Logic.

Flutter مسؤول عن:

Presentation
Navigation
User Interaction
Localization

Rust مسؤول عن:

Engineering Model
Validation
Commands
Geometry
Persistence
Engineering calculations

========================================
6. COMMAND ARCHITECTURE

بعد Foundation Hardening، وسّع ModelCommand تدريجيًا.

ابدأ فقط بالتصميم والبنية الضرورية.

المسار المستهدف:

User Action
↓
Validated Command
↓
Engineering Model
↓
revision++
↓
Updated State/Summary

يجب منع أي مسار يسمح بتجاوز validation.

لكن لا تبنِ الآن نظام Undo/Redo كاملًا.

ولا تبنِ Collaboration.

ولا Event Sourcing كاملًا.

صمّم extension points فقط إذا كانت ضرورية.

========================================
7. GEOMETRY MUST REMAIN THE NEXT MAJOR TARGET

بعد Foundation Hardening وArabic Foundation المحدودة:

نريد الانتقال مباشرة إلى Geometry.

لا نريد أن تتحول Arabic UI إلى مرحلة طويلة تؤخر Geometry.

التسلسل:

Engineering Model
↓
Parametric Geometry Service
↓
GeometryKernel Trait
↓
Kernel Adapter
↓
Concrete Kernel

========================================
8. CADRUM / OCCT SPECIAL RULE

بسبب مشكلة مساحة التخزين السابقة:

ممنوع البدء مباشرة بتنزيل OCCT كبير.

قبل أي integration حقيقي:

نفذ Geometry Kernel Probe منفصلًا.

يجب أن يتحقق من:

- cadrum version
- OCCT version
- dependency size
- download size
- extraction size
- build requirements
- compile time
- runtime API
- Linux compatibility
- Android feasibility
- iOS feasibility
- Web/WASM feasibility
- license
- API stability

إذا كان هناك احتمال كبير لاستنزاف مساحة البيئة:

توقف قبل تنزيل binary كبير.

لا تكرر تجربة STEP 4B السابقة التي أدت إلى امتلاء filesystem.

========================================
